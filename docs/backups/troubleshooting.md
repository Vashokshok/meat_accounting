# Типовые проблемы и правила для прода

## Как понять, что всё работает

Самый быстрый сигнал — последняя строка `backup.log`:

| Строка в логе | Значение |
|---|---|
| `OK: ... (размер байт), backups kept: N` | бэкап прошёл успешно |
| `ERROR: ...` | что-то сломалось, следующая строка — причина |
| Строки вообще нет за понедельник | бэкап не запускался (задача/cron не сработал) |

## Таблица проблем

| Симптом | Причина | Решение |
|---|---|---|
| В логе `container not running` | Контейнер БД выключен | Linux: `docker compose start db`; Windows: `docker start meat_db` |
| В логе `pg_dump failed` | Нет доступа пользователя БД | Linux: `docker compose exec db psql -U meat -d meat`; Windows: `docker exec -it meat_db psql -U meat -d meat` |
| Файл дампа 0 байт | Сбой записи, диск заполнен | `df -h`, удалить старые дампы вручную |
| `pg_restore -l` ругается / пусто | Дамп повреждён | Восстановить предыдущий дамп, проверить ротацию |
| Задача не появляется (Windows) | Планировщик не запустил | `Get-ScheduledTaskInfo -TaskName MeatAccounting_WeeklyBackup`; перерегистрировать по `deploy.md` |
| В логе `removed old backup` каждый раз | Место копится быстрее 60 дней | Уменьшить `RETENTION_DAYS` в скрипте или вынести часть во внешний архив |
| `docker` не отвечает | Демон Docker выключен | Запустить Docker Desktop (Windows) или `systemctl start docker` (Linux) |
| Восстановление падает на `CREATE DATABASE` | Дамп создает базу, а она уже есть | Целиться в пустую базу: `--clean --if-exists` или создавать новую |

## Мониторинг

Проверять регулярно (раз в неделю, в момент появления «нового» понедельничного
бэкапа):

```powershell
# Windows
Get-ChildItem C:\backups\meat\*.dump | Sort-Object LastWriteTime -Descending
Get-Content C:\backups\meat\backup.log -Tail 10
```

```bash
# Linux
ls -lh /var/backups/meat/
tail -10 /var/backups/meat/backup.log
du -sh /var/backups/meat   # размер каталога, чтобы место не заканчивалось
```

## Правила для прода

1. Раз в месяц — тренировочное восстановление в пустую базу (см. `restore.md`)
   и прогон тестов: `pytest tests/`.
2. Ручной бэкап сразу после выкладки крупной миграции: Linux — запустить
   `scripts/backup.sh` с `CONTAINER="$(docker compose ps -q db)"`;
   Windows — использовать `scripts/backup.ps1`.
3. Бэкапы на том же диске — не полноценная защита: настроить копию на внешнее
   хранилище (шаг 6 `deploy.md`).
4. Дампы НЕ зашифрованы: бинарный формат — это не секретность. Кто получил
   доступ к файлу, тот получил данные (включая bcrypt-хеши паролей). Ограничить
   права на каталог: на Linux `chmod 700 /var/backups/meat`, владелец —
   служебный аккаунт; при необходимости — шифровать дампы перед хранением
   (`gpg -c`, `openssl enc -aes-256-cbc`).
5. Пароль БД и место хранения бэкапов держать вне документации и кода.
6. Задание Cron/Планировщика — часть деплоя: проверять на каждом новом сервере.
